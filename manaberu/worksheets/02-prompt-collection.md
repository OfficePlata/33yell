# プロンプト集（AIへの頼み方）

`（ ）` の部分を自分の内容に置き換えて使います。個人情報・秘密情報は入れないでください。

## P-01 業務文書を作る（第2回）
```
あなたは（業種）の業務改善コンサルタントです。
目的：（スタッフ3名）向けに（予約受付のルール）を作りたいです。
今のやり方：（電話でメモ帳に書いている）
困りごと：（ダブルブッキング、伝え忘れ）
形：A4 1枚に収まる箇条書き。最初に3行の要約を付けてください。
```

## P-02 要件の壁打ち（第2回）
```
私は（作りたいもの）をLarkで作りたいと考えています。
下の設計シートを読み、足りない情報を1つずつ質問してください。
質問は1回に1つ、最大10問まで。最後に設計シートの形にまとめてください。
---
（設計シートを貼り付け）
```

## P-03 BASE設計（第4回）
```
Lark BASEで（作りたいもの）を作ります。
次の要件から、テーブルの分け方と、各テーブルのフィールド（名前・種類・例）を表で提案してください。
フィールドの種類は Lark BASE にあるもの（テキスト、数値、日付、単一選択、ユーザー、リンク、数式など）から選んでください。
同じ情報を何度も入力しなくて済むよう、テーブル同士のリンクも提案してください。
---
（設計シートの「4. 要件」を貼り付け）
```

## P-04 操作マニュアル（第5回）
```
次の操作を、ITに慣れていないスタッフ向けのマニュアルにしてください。
1ページ1操作、画面の順番どおりに番号付きで。専門用語には一言説明を付けてください。
操作：（BASEの「本日の予約」ビューを開いて、来店済みにする）
```

## P-05 受付ページ（第8回）
```
（お店・会社名）の（予約）受付ページを index.html で作ってください。
- スマホで見やすく、入力欄は大きめに
- 入力項目：（お名前、来店日時、人数、ご要望）
- 必須項目が空なら送信できないように
- 今回は見た目だけで、送信先はまだ作らないでください
作る前に、不明点があれば質問してください。できたら確認方法を教えてください。
```

## P-06 BASEへ保存（第9回）
```
受付ページの送信内容を、Lark BASEの1テーブルに1件追加したいです。
- Cloudflare Pages Functions で /api/reserve を作り、ページからはそこへ送ってください
- Lark の tenant_access_token を取得し、Bitable の「レコード追加」APIを使ってください
- App ID などは環境変数 LARK_APP_ID / LARK_APP_SECRET / LARK_BASE_TOKEN / LARK_TABLE_ID から読み、コードに直接書かないでください
- BASEのフィールド名と種類：（お名前＝テキスト、来店日時＝日付、人数＝数値、受付経路＝単一選択）
- 送信に成功・失敗したら、ページにわかりやすく表示してください
作る前に、手順を説明してください。
```

## P-07 LIFF対応（第10回）
```
受付ページを LINE の LIFF で開けるようにしたいです。LIFF ID は（LIFF ID）です。
- LIFF SDK を読み込み、liff.init() してください
- LINEの外で開いた場合でも、通常のフォームとして使えるようにしてください
- 送信時に liff.getIDToken() の値を一緒に /api/reserve へ送ってください
```

## P-08 LINEユーザーの確認と保存（第10回）
```
/api/reserve で、送られてきた LINE の IDトークンを LINE の検証API（https://api.line.me/oauth2/v2.1/verify）で確認してください。
client_id は環境変数 LINE_CHANNEL_ID から読んでください。
検証に成功した場合だけ、ユーザーID（sub）を BASE の「LINEユーザーID」に、受付経路を「LINE」で保存してください。
IDトークンがない場合は、受付経路「フォーム」として保存してください。
```
