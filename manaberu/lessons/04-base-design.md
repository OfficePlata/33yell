# 第4回 BASEでデータの入れ物を設計する

## この回のゴール
- テーブル・フィールド・レコードの意味がわかる
- 自社用のBASE（2テーブル以上、リンクあり）を作れている

## 説明① 表計算とデータベースの違い
| 用語 | たとえ | 例（まなべ食堂） |
|---|---|---|
| BASE | 台帳のファイル | 「まなべ食堂 台帳」 |
| テーブル | 台帳の中の1冊 | 顧客／予約／弁当注文 |
| フィールド | 列（項目） | 来店日時、人数、ステータス |
| レコード | 行（1件分） | 山田さんの10/10の予約 |

Excelとの大きな違い：
- **フィールドに「種類」がある**（日付・数値・単一選択・ユーザー・添付など）→ 入力ミスを防げる
- **テーブル同士をリンクできる** → 同じ情報を何度も書かなくてよい
- 複数人で同時に使える、権限を付けられる、自動化できる

### よく使うフィールドの種類
| 種類 | 使いどころ |
|---|---|
| テキスト／複数行テキスト | 名前、メモ |
| 数値・通貨 | 個数、金額 |
| 日付 | 予約日、期限 |
| 単一選択／複数選択 | ステータス、分類（表記ゆれを防ぐ） |
| ユーザー | 担当者（通知先にもなる） |
| 添付ファイル | 写真、見積書 |
| リンク（双方向リンク） | 別テーブルの1件を指す |
| 数式 | 金額＝個数×単価 |
| 自動採番・作成日時 | 番号や記録を自動で残す |

## ハンズオン① Excelを取り込む
1. BASEを新規作成し、宿題で用意したExcelを取り込む（インポート）
2. 取り込まれた各列の「種類」を見直す（日付が文字になっていないか、ステータスを単一選択にする）
3. 主フィールド（いちばん左の列）を、1件を見分けられる項目にする

## 説明② テーブルを分ける・つなぐ
- 「同じ内容を何度も書いている列」があれば、別テーブルに分けるサインです。
  - 例：予約のたびに顧客名・電話番号を書いている → 「顧客」テーブルに分け、予約からリンクする
- 分け方に迷ったら「その情報は1つか、何度も起きるか」で考えます（顧客は1人1件、予約は何度も起きる）。

## ハンズオン② 2テーブル以上で設計する
1. 紙またはAIで、テーブルとフィールドの一覧を作る（プロンプト集「P-03 BASE設計」）
2. 2つ目のテーブルを作り、リンクフィールドでつなぐ
3. 1件入力して、リンク先から元のテーブルが見えることを確かめる
4. 設計（テーブル名・フィールド名・種類）をWikiの「02 業務ルール」に貼る

## つまずきやすい点
- 1つのテーブルに全部詰め込む → 列が50を超えたら分けどき
- 選択肢を自由入力にする → 表記ゆれで集計できなくなる。単一選択にする
- フィールド名を後から変えると、自動化やAPI（第9回）に影響する → 早めに決める

- ダミーデータを20件入れる（AIに「架空の予約データを20件、表形式で」と頼んで作ってよい）
