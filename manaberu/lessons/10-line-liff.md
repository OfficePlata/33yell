# 第10回 LINEとつなぐ（LIFF）

## この回のゴール
- LINEの中で自分の受付ページを開ける
- 「LINEで予約 → BASEに保存 → 社内のLarkに通知」が通しで動く

> LINE連携が不要な方の代替課題：受付ページに「確認画面」と「送信完了メール文面の自動作成（AI）」を足す。

## 説明① LINE公式アカウントとLIFF
| 言葉 | 意味 |
|---|---|
| LINE公式アカウント | お店・会社のLINE。お客様が友だち追加する |
| リッチメニュー | トーク画面の下に出るボタン。予約などの入口にする |
| LIFF（リフ） | LINEの中で開くWebページ。**第8〜9回で作ったページを、そのままLINEの中で使える** |
| LINE Developers | LIFFなどの開発用設定をする管理画面 |

LIFFを使う良いところ：
- お客様はアプリを入れなくてよい、LINEのまま予約できる
- お客様のLINE上の名前・ID（本人の許可のうえ）を受け取れる → 「誰の予約か」をBASEで追える

## ハンズオン① LIFFアプリを作る
1. LINE Developers にログインし、プロバイダー（会社名など）を作る
2. 「LINEログイン」チャネルを作る
3. チャネルの「LIFF」タブで LIFFアプリを追加
   - エンドポイントURL：第8回の公開URL（例：`https://manabe.pages.dev/`）
   - スコープ：`profile` と `openid`
4. 発行された LIFF ID を控える（これは秘密情報ではありません）
5. Claude Code に「P-07 LIFF対応」で頼み、ページをLIFFに対応させる
6. スマホのLINEで `https://liff.line.me/（LIFF ID）` を開き、ページが表示されることを確かめる

## 説明② だれの予約かをつなぐ
- ページ側（LIFF）で、お客様のIDトークンを受け取る
- 受付係（第9回の Functions）で、IDトークンをLINEのサーバーに問い合わせて **本物か確かめてから** 、LINEユーザーIDと名前をBASEに保存する
  - ページから送られてきた「ユーザーID」をそのまま信じない（なりすまし対策）
- 受付後、第6回の自動化で店のLarkグループに通知が届く。届かない場合は、Larkのグループにカスタムボットを追加し、そのWebhook URLへ受付係から通知を送る（WebhookのURLもシークレットに登録）

## ハンズオン② 通しで動かす
1. Cloudflare に `LINE_CHANNEL_ID`（LINEログインチャネルのID）をシークレット登録する
2. Claude Code に「P-08 LINEユーザーの確認と保存」で頼む
3. LINEから予約 → BASEに「LINEユーザーID」「受付経路＝LINE」で入る → Larkに通知、を確かめる
4. LINE公式アカウントの管理画面で、リッチメニューに「予約する」ボタンを作り、リンク先を `https://liff.line.me/（LIFF ID）` にする

## 守ること
- お客様の情報を受け取るので、ページに「何の情報を・何のために使うか」を一言書く
- テストは、自分や社内のLINEアカウントで行う

## 宿題
- 社内の2人以上にLINEから予約してもらい、通しで動くかテストする
