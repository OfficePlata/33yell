# 第8回 Webに公開する

## この回のゴール
- 作ったページを Cloudflare Pages で公開し、URLをスマホで開ける
- 修正して GitHub に保存すると、公開ページにも自動で反映される

## 説明① 公開のしくみ
- Webページを公開する＝ **「誰でも取りに来られる場所（サーバー）にファイルを置く」** こと
- Cloudflare Pages は、GitHubに保存したファイルを自動で公開してくれるサービス（無料枠あり）
- 流れ：PCで作る → GitHubに保存 → Cloudflareが自動で公開 → `https://（名前）.pages.dev` で見られる

## ハンズオン① GitHubとつないで公開
1. Cloudflareにログインし、「Workers & Pages」から Pages のプロジェクトを作る
2. 「Gitに接続」を選び、第7回のリポジトリを選ぶ
3. ビルドの設定は、HTMLだけなら「フレームワークなし」、ビルドコマンドは空、出力先は `/`（ルート）
4. 公開されたURLを、自分のスマホで開く

うまくいかないときは、画面のエラー文をそのまま Claude Code に貼って「Cloudflare Pagesで公開したらこうなった。原因と直し方を教えて」と頼みます。

## 説明② スマホで見やすく・自動で反映
- お客様の多くはスマホで見ます。PCとスマホの両方で確認するクセをつけます。
- GitHubに保存するたびに、Cloudflareが自動で公開し直します（数十秒〜数分）。
- 公開＝誰でも見られる、ということ。**個人情報や社内情報をページに書かない**。

## ハンズオン② 受付ページを作って公開
1. Claude Code に受付ページを頼む（プロンプト集「P-05 受付ページ」）
   - この回は「見た目だけ」。送信ボタンを押しても、まだどこにも送られなくて大丈夫です
2. スマホで確認し、直したい点を2つ直す
3. 記録 → GitHubに保存 → 公開URLに反映されたことを確かめる

## 宿題
- 公開URLを社内で見てもらい、直したい点を3つ集める（BASEの「改善要望」テーブルに入れておくと第11回で使えます）
