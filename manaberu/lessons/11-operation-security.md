# 第11回 安全に運用・改善する

## この回のゴール
- 作ったしくみを「止めない・漏らさない・直せる」状態で運用するルールがある
- 改善要望を1つ、Claude Codeで直して公開できている

## 説明① 運用で気をつける4つ
| 観点 | 確かめること |
|---|---|
| 権限 | BASE・Wiki・アプリを「誰が見られる／編集できるか」。退職・異動のときに外す手順があるか |
| 個人情報 | 集める項目は必要最小限か。公開ページに表示していないか。目的を伝えているか |
| 秘密情報 | App Secret などがGitHub・チャット・ファイルに残っていないか。漏れたら作り直す（ローテーション） |
| 止まったとき | 誰が気づくか、誰に連絡するか、その間は電話受付に戻すなどの代わりの手段 |

- BASEは定期的にコピーやエクスポートで控えを取っておくと安心です。

## ハンズオン① 運用ルール表を作る
[../worksheets/03-operation-rules.md](../worksheets/03-operation-rules.md) を自社用に埋め、Wikiの「02 業務ルール」に置きます。AIに「この表で抜けている観点はありますか」と聞いて見直します。

## 説明② 改善の回し方
1. 要望はBASEの「改善要望」テーブルに集める（誰が・何に困ったか・どのくらい困るか）
2. 月1回、効果×手間で選ぶ
3. 直す前に「Gitで記録」→ Claude Codeに頼む → 手元で確認 → 公開 → 依頼者に確認してもらう
4. 直した内容をWikiの「04 改善メモ」に1行残す

AIに直させるときのコツ：
- 「どこを・どう変えたいか・変えてはいけないところ」を伝える
- 直したあとに「何を変えたか説明して」と頼み、自分でも読む
