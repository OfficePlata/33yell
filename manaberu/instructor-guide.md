# 講師ガイド（笹原さん用）

## 1. 講座の設計方針
- **ノーコード（Lark）→ AIでコード** の順。最初からコードに入ると、未経験者がフェーズ3の前に離脱しやすいため。
- ゴールは受講者を自社の「構築者」にすること。全12回を通して「自社で実際に使うしくみ1つ」を作り、公開まで届ける。共通サンプル（まなべ食堂）は講師デモ用。題材が決まらない人だけサンプルで始め、第2週までに自社題材へ切り替える。
- 4〜6名・8週間の集中型。前半（Lark）は週2回、後半（AI開発）は手を動かす時間を取るため週1回。
- 講師は答えのコードを渡さず、「次に何を試すか」と「AIへの頼み方」を返す（マカセルと同じ方針）。
- 1回90分＝説明10分×2＋ハンズオン20分×2＋ふりかえり・質疑。

## 2. 回ごとのつまずきポイント
| 回 | つまずきやすい点 | 先回りの手当て |
|---|---|---|
| 1 | 作りたいものが大きすぎる（「基幹システム」など） | 「毎週くり返す・関係者2〜5人・失敗しても大事故にならない」で絞らせる |
| 2 | AIの答えをそのまま使う | 「現場の人が読んでわかるか」を必ず確認させる |
| 3 | 社内Larkの権限が足りない | 第1回までに管理者へ相談するよう、事前案内に入れる |
| 4 | 1テーブルに全部詰め込む／選択肢を自由入力 | 「同じことを何度も書いていないか」で分割を問いかける |
| 6 | 自動化のプラン上限 | 事前にプランを確認。上限がある場合は通知の本数を絞る |
| 7 | Windowsのインストールで止まる | 開講前の準備会（30分）でインストールまで済ませる |
| 7 | コマンド実行の許可を何でも押す | 「読んでから許可、わからなければ聞く」を毎回くり返す |
| 9 | 開発者コンソールの権限公開・BASEへのアプリ追加を忘れる | 手順をチェックリストにして画面共有で一緒に進める |
| 9 | Secret をコードやチャットに貼る | 画面共有前に必ず確認。貼ってしまったら即再発行させる |
| 10 | LINEログインチャネルとMessaging APIチャネルの混同 | LIFFは「LINEログイン」チャネルに作ると明示 |

## 3. 事前に確かめておくこと（教材の前提）
- Lark・Cloudflare・LINE Developers・Claude Code の画面や手順は更新されることがある。**開講前に講師環境で第4〜10回を一通り通し、画面名が教材と合っているか確認する**。
- BASEの自動化が「APIで追加されたレコード」でも動くかを講師環境で確認する（第10回で代替手段＝カスタムボットWebhookを用意済み）。
- 講師デモ用に、共通サンプル「まなべ食堂」の完成版（BASE・公開ページ・LIFF）を作っておく。

## 6. 2ヶ月集中で回すための運営
- **開講前の準備会（30分）**：Claude Code・Git・各アカウントの準備を開講前に終わらせる。第4週に環境構築で止まると、後半が崩れる。
- **題材の大きさチェック（第1回）**：2ヶ月で公開まで届く範囲に切る。「最初に公開する範囲」と「修了後に足す範囲」を分ける。
- **週2回の週は宿題を軽く**：第1〜3週は宿題30〜60分、第4週以降は週2〜3時間を目安に。
- **個別レビュー（第6週・1人30分）**：API連携の前後でつまずきやすいので、ここで1人ずつ設計と秘密情報の扱いを確認する。
- **遅れた人の救済**：第9回（API）まで進めない人は、BASE＋フォーム＋自動化（フェーズ2）を本番運用に乗せることを優先し、AI開発の部分は修了後のマカセルにつなぐ。

## 7. 模擬講義でわかったこと（第1回・2026-10-02）
[第1回 講師台本](lessons/01-talk-script.md) を、1分あたり250字（講義向けのゆっくりめ）で見積もった結果です。

| わかったこと | 対応 |
|---|---|
| 説明パートは、台本を読むだけだと各10分のうち2分前後で終わる | 説明①に講師デモ版「まなべ食堂」の実演（4分）と受講者との対話（2分）を、説明②に「自己紹介で出た業務を全員で4つの型に分類」（5分）を組み込んだ |
| 組み込んだあとの合計は約68分で、90分に対して約22分の余裕がある | 初回は接続トラブル・遅刻・質問で押しやすいため、余裕として残す。最後の区切りを「共有・質問・宿題」に名前を変え、質問の時間であることを明示した |
| 自己紹介と共有は人数で長さが決まる（1人1分×6名） | 6名の回は時間どおり。4名の回は早く終わるので、その分を質問に回す |

第2回以降も、台本を書いたら `slides/src/talk-check.js` で同じように確かめる。

## 8. 各回の講師準備（共通）
- 前回の宿題の提出状況を確認し、つまずいている人に一言かける
- 当日のハンズオンを講師環境で通しておく
- 講座グループに当日の資料リンク（Wiki）を投稿しておく
